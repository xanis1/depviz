# depviz

CLI-инструмент визуализации графа зависимостей для менеджера пакетов npm.
Вся логика получения метаданных и обхода графа пишется самостоятельно
на стандартной библиотеке Python (3.9+), без менеджеров пакетов и
сторонних библиотек.

Проект разрабатывается поэтапно (этапы 1-5), каждый этап фиксируется
отдельным коммитом. Текущее состояние: **этап 4** (обратные зависимости).

## 1. Общее описание

Приложение принимает параметры из командной строки, проверяет их, получает
сведения о пакетах (из npm-репозитория по HTTP или из файла тестового
репозитория) и строит граф зависимостей с учетом транзитивности.

Граф строится алгоритмом BFS с рекурсией: каждый вызов `visit_level`
обрабатывает один уровень графа и рекурсивно вызывает себя для следующего.
Множество уже обнаруженных пакетов гарантирует, что каждый пакет
обрабатывается один раз, поэтому циклические зависимости не зацикливают
обход. Узлы графа - имена пакетов.

Структура проекта:

- `src/depviz/config.py` - разбор и проверка опций, класс `Config`;
- `src/depviz/registry.py` - HTTP-запрос метаданных пакета, разбор JSON;
- `src/depviz/npm_metadata.py` - версия `latest`, поле `dependencies`,
  имена пакетов в реестре (алиасы `npm:`);
- `src/depviz/sources.py` - источники данных: `RegistrySource` (URL) и
  `ReverseSource` (обратные связи для режима `reverse`);
- `src/depviz/file_repository.py` - `FileRepository`: тестовый репозиторий
  из файла, прямые и обратные связи пакетов;
- `src/depviz/graph.py` - `GraphBuilder`: рекурсивный BFS, уровни, фильтр,
  циклы;
- `src/depviz/cycles.py` - поиск циклических зависимостей;
- `src/depviz/collector.py` - выбор источника и сбор данных;
- `src/depviz/report.py` - форматирование результатов для вывода;
- `src/depviz/cli.py` - запуск, коды завершения;
- `src/depviz/errors.py` - исключения приложения;
- `tests/` - модульные тесты (`unittest`), локальный HTTP-сервер
  `tests/fake_registry.py` (имитация npm-репозитория, интернет не нужен)
  и тестовые репозитории `tests/data/*.txt`;
- `run.bat` - запуск приложения и тестов в Windows.

Особенности работы с реальным репозиторием:

- для каждого пакета берется последняя версия (`dist-tags.latest`), а в
  граф входит поле `dependencies`; `devDependencies`, `peerDependencies` и
  `optionalDependencies` не учитываются;
- алиасы `npm:имя@диапазон` заменяются настоящим именем пакета;
  зависимости из git, URL и файлов пропускаются;
- метаданные запрашиваются по адресу `<репозиторий>/<имя пакета>`, слеш в
  имени пакета с областью видимости кодируется (`@babel/core` ->
  `@babel%2Fcore`);
- пакеты запрашиваются последовательно, для крупных пакетов обход может
  занять десятки секунд.

## 2. Параметры командной строки

| Опция                | Описание                                                                |
|----------------------|-------------------------------------------------------------------------|
| `-p`, `--package`    | Имя анализируемого пакета (обязательная).                               |
| `-r`, `--repo`       | URL репозитория или путь к файлу тестового графа.                       |
| `-t`, `--test-mode`  | Режим тестового репозитория: `--repo` - путь к файлу.                   |
| `-a`, `--ascii-tree` | Вывод зависимостей в формате ASCII-дерева (этап 5).                     |
| `-f`, `--filter`     | Не учитывать пакеты, в имени которых есть подстрока.                    |
| `-s`, `--show`       | Что вывести: `config`, `direct`, `graph`, `reverse` (обратные зависимости).         |

Опция `--show` по умолчанию равна `graph`. Значение `config` сохраняет
поведение этапа 1 (вывод проверенных параметров без обращения к данным),
значение `direct` - поведение этапа 2 (прямые зависимости пакета по URL,
режим `--test-mode` с ним не работает), значение `reverse` - поведение
этапа 4 (обратные зависимости пакета, работает только с `--test-mode`).

Правила проверки:

- обычный режим: имя пакета по правилам npm (строчные буквы, цифры,
  `-._~`, необязательный префикс `@область/`, не длиннее 214 символов);
  `--repo` должен быть адресом `http(s)://хост`, по умолчанию
  `https://registry.npmjs.org`;
- тестовый режим: имя пакета состоит из больших латинских букв `A-Z`;
  `--repo` обязателен и указывает на существующий файл;
- подстрока фильтра непустая, без пробельных символов, регистр учитывается;
  фильтр не должен исключать сам анализируемый пакет;
- неизвестные и сокращенные опции отклоняются.

Фильтр: пакет, в имени которого есть подстрока, не запрашивается, не
попадает в граф, и его собственные зависимости не анализируются (если
они не достижимы другим путем).

Формат файла тестового репозитория: одна строка на пакет, `ПАКЕТ: ЗАВИСИМОСТИ`.
Имена - большие латинские буквы, зависимости разделяются пробелами или
запятыми, пустые строки игнорируются. Пакет, упомянутый только как
зависимость, считается пакетом без зависимостей. Пример (`diamond.txt`):

    A: B C
    B: D
    C: D
    D:

Вывод графа: строка `пакет -> зависимости` для каждого узла в порядке обхода
BFS, затем список найденных циклов. Цикл записывается цепочкой, в которой
первый и последний пакет совпадают; для каждого обратного ребра обхода в
глубину выводится один цикл.

Обратные зависимости (`--show reverse`): для пакета `--package` находятся все
пакеты тестового репозитория, которые зависят от него напрямую или через
другие пакеты. Используется тот же рекурсивный BFS, что и для графа: источник
данных `ReverseSource` на каждом шаге возвращает не зависимости пакета, а
зависящие от него пакеты. Результат делится на уровни: на уровне 1 пакеты,
зависящие от заданного напрямую, на уровне 2 - зависящие от пакетов уровня 1
и так далее. Сам пакет в список не включается, его участие в цикле
показывает раздел циклических зависимостей, где цепочка записана в
направлении `<-` (`A <- C` - `C` зависит от `A`). Фильтр `--filter` исключает
пакеты из результата так же, как в режиме `graph`. Реестр npm не хранит
сведений об обратных зависимостях, поэтому с репозиторием по URL режим
`reverse` недоступен (ошибка параметров, код `2`).

Коды завершения: `0` - успех, `2` - ошибка параметров, `3` - ошибка
получения или анализа данных (нет сети, пакет не найден, статус HTTP не 200,
некорректный ответ или файл, слишком глубокий граф). Сообщение об ошибке
выводится в stderr.

## 3. Сборка и тесты (Windows)

Сборка не требуется, нужен только Python 3.9 или новее в `PATH`.

    run.bat -p express
    run.bat -t -p A -r tests\data\diamond.txt
    run.bat test

`run.bat test` запускает все модульные тесты из каталога `tests/`. Для
запуска приложения с реальным репозиторием нужен доступ в интернет к
`registry.npmjs.org`, для тестов и тестового режима - нет.

## 4. Примеры использования

Тестовые репозитории лежат в `tests\data`: `simple`, `diamond` (общая
зависимость), `cycle` (цикл через корень), `inner_cycle` (цикл внутри графа),
`self_loop` (зависимость от самого себя), `disconnected` (недостижимые
пакеты), `chain`, `mixed` (общие зависимости и цикл).

Общая зависимость, пакет `D` выводится один раз:

    run.bat -t -p A -r tests\data\diamond.txt
    Граф зависимостей пакета A: узлов 4, ребер 4
    A -> B, C
    B -> D
    C -> D
    D -> (нет зависимостей)
    Циклические зависимости: не обнаружены

Цикл через корневой пакет:

    run.bat -t -p A -r tests\data\cycle.txt
    Граф зависимостей пакета A: узлов 3, ребер 3
    A -> B
    B -> C
    C -> A
    Циклические зависимости (1):
      A -> B -> C -> A

Цикл внутри графа и зависимость от самого себя:

    run.bat -t -p A -r tests\data\inner_cycle.txt
    ...
    Циклические зависимости (1):
      B -> C -> B

    run.bat -t -p A -r tests\data\self_loop.txt
    ...
    Циклические зависимости (1):
      A -> A

Общие зависимости и цикл `A -> D -> H -> A`:

    run.bat -t -p A -r tests\data\mixed.txt
    Граф зависимостей пакета A: узлов 11, ребер 15
    A -> B, C, D
    B -> E, F
    C -> F, G
    D -> G, H
    E -> I
    F -> I, J
    G -> J
    H -> A
    I -> (нет зависимостей)
    J -> K
    K -> (нет зависимостей)
    Циклические зависимости (1):
      A -> D -> H -> A

Фильтр: пакет `H` исключен, цикл исчез.

    run.bat -t -p A -r tests\data\mixed.txt -f H
    Граф зависимостей пакета A: узлов 10, ребер 13
    ...
    Циклические зависимости: не обнаружены

Пакет не из корня графа и недостижимые пакеты (`X`, `Y` не выводятся):

    run.bat -t -p B -r tests\data\mixed.txt
    run.bat -t -p A -r tests\data\disconnected.txt

Обратные зависимости (этап 4), общая зависимость `D` из `diamond.txt`:

    run.bat -t -p D -r tests\data\diamond.txt -s reverse
    Обратные зависимости пакета D (всего 3):
      уровень 1: B, C
      уровень 2: A
    Циклические зависимости: не обнаружены

Пакет, от которого никто не зависит, и цикл через корень (`A <- C <- B <- A`):

    run.bat -t -p A -r tests\data\simple.txt -s reverse
    Обратные зависимости пакета A: отсутствуют
    Циклические зависимости: не обнаружены

    run.bat -t -p A -r tests\data\cycle.txt -s reverse
    Обратные зависимости пакета A (всего 2):
      уровень 1: C
      уровень 2: B
    Циклические зависимости (1):
      A <- C <- B <- A

Глубокий граф `mixed.txt`: пять уровней и цикл вдали от пакета `K`.

    run.bat -t -p K -r tests\data\mixed.txt -s reverse
    Обратные зависимости пакета K (всего 8):
      уровень 1: J
      уровень 2: F, G
      уровень 3: B, C, D
      уровень 4: A
      уровень 5: H
    Циклические зависимости (1):
      A <- H <- D <- A

Фильтр исключает пакет `B` из результата:

    run.bat -t -p D -r tests\data\diamond.txt -s reverse -f B
    Обратные зависимости пакета D (всего 2):
      уровень 1: C
      уровень 2: A
    Циклические зависимости: не обнаружены

Ошибки:

    run.bat -t -p Z -r tests\data\simple.txt
    Ошибка: пакет 'Z' не найден в репозитории 'tests\data\simple.txt'
    run.bat -p express -s reverse
    Ошибка: режим reverse работает только с тестовым репозиторием (--test-mode): ...
    run.bat -t -p A -r tests\data\simple.txt -f A
    Ошибка: пакет 'A' содержит подстроку фильтра 'A' и был бы исключен из анализа

Реальный репозиторий (граф последних версий пакетов):

    run.bat -p express
    run.bat -p express -f debug
    run.bat -p express -s direct
