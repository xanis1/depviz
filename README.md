# depviz

CLI-инструмент визуализации графа зависимостей для менеджера пакетов npm.
Вся логика получения метаданных и обхода графа пишется самостоятельно
на стандартной библиотеке Python (3.9+), без менеджеров пакетов и
сторонних библиотек.

Проект разрабатывается поэтапно (этапы 1-5), каждый этап фиксируется
отдельным коммитом. Текущее состояние: **этап 2** (прямые зависимости).

## 1. Общее описание

Приложение принимает параметры из командной строки, проверяет их, загружает
метаданные пакета из npm-репозитория по HTTP (`urllib` из стандартной
библиотеки) и выводит его прямые зависимости.

Структура проекта:

- `src/depviz/config.py` - разбор и проверка опций, класс `Config`;
- `src/depviz/registry.py` - HTTP-запрос метаданных пакета, разбор JSON;
- `src/depviz/npm_metadata.py` - версия `latest` и поле `dependencies`;
- `src/depviz/collector.py` - сбор данных в соответствии с конфигурацией;
- `src/depviz/cli.py` - форматирование вывода и коды завершения;
- `src/depviz/errors.py` - исключения приложения;
- `tests/` - модульные тесты (`unittest`) и локальный HTTP-сервер
  `tests/fake_registry.py`, имитирующий npm-репозиторий (интернет не нужен);
- `run.bat` - запуск приложения и тестов в Windows.

Прямыми зависимостями считается поле `dependencies` последней версии пакета
(версия берется из `dist-tags.latest`). Поля `devDependencies`,
`peerDependencies` и `optionalDependencies` не учитываются. Метаданные
запрашиваются по адресу `<репозиторий>/<имя пакета>`; для пакета с областью
видимости слеш кодируется (`@babel/core` -> `@babel%2Fcore`).

## 2. Параметры командной строки

| Опция                | Описание                                                          |
|----------------------|-------------------------------------------------------------------|
| `-p`, `--package`    | Имя анализируемого пакета (обязательная).                         |
| `-r`, `--repo`       | URL репозитория или путь к файлу тестового графа.                 |
| `-t`, `--test-mode`  | Режим тестового репозитория: `--repo` - путь к файлу.             |
| `-a`, `--ascii-tree` | Вывод зависимостей в формате ASCII-дерева.                        |
| `-f`, `--filter`     | Не учитывать пакеты, в имени которых есть подстрока.              |
| `-s`, `--show`       | Что вывести: `config` - параметры, `direct` - прямые зависимости. |

Опция `--show` по умолчанию равна `direct`. Значение `config` сохраняет
поведение этапа 1: приложение только выводит проверенные параметры, не
обращаясь к сети. Опции `--ascii-tree`, `--filter` и тестовый режим для
получения зависимостей будут задействованы на следующих этапах.

Правила проверки:

- обычный режим: имя пакета по правилам npm (строчные буквы, цифры,
  `-._~`, необязательный префикс `@область/`, не длиннее 214 символов);
  `--repo` должен быть адресом `http(s)://хост`, по умолчанию
  `https://registry.npmjs.org`;
- тестовый режим: имя пакета состоит из больших латинских букв `A-Z`;
  `--repo` обязателен и указывает на существующий файл;
- подстрока фильтра непустая и без пробельных символов;
- неизвестные и сокращенные опции отклоняются.

Коды завершения: `0` - успех, `2` - ошибка параметров, `3` - ошибка
получения данных (нет сети, пакет не найден, статус HTTP не 200,
некорректный ответ). Сообщение об ошибке выводится в stderr.

## 3. Сборка и тесты (Windows)

Сборка не требуется, нужен только Python 3.9 или новее в `PATH`.

    run.bat -p express
    run.bat -p express -s config
    run.bat test

`run.bat test` запускает все модульные тесты из каталога `tests/`. Для
запуска приложения нужен доступ в интернет к `registry.npmjs.org`, для
тестов - нет.

## 4. Примеры использования

Формат вывода прямых зависимостей (условный пакет и локальный репозиторий):

    run.bat -p demo-app -r http://localhost:8080
    Прямые зависимости demo-app@2.4.0 (3):
      @scope/util (~4.1.2)
      chalk (5.3.0)
      left-pad (^1.3.0)

Пакет без зависимостей и ошибки:

    Прямые зависимости leaf@0.1.0: отсутствуют
    Ошибка: пакет 'absent' не найден в репозитории 'http://localhost:8080'
    Ошибка: имя пакета 'Express' не соответствует правилам npm: ...

Вывод параметров (поведение этапа 1):

    run.bat -p express -a -f test -s config
    package: express
    repo: https://registry.npmjs.org
    test_mode: false
    ascii_tree: true
    filter: test
    show: config
