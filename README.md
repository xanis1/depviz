# depviz

CLI-инструмент визуализации графа зависимостей для менеджера пакетов npm.
Вся логика получения метаданных, разбора и обхода графа написана
самостоятельно на стандартной библиотеке Python (3.9+): менеджеры пакетов и
сторонние библиотеки не используются.

## 1. Общее описание

Инструмент принимает параметры из командной строки, получает сведения о
пакетах (из npm-репозитория по HTTP или из файла тестового репозитория),
строит граф зависимостей с учетом транзитивности и выводит его:

- в виде текстового описания на языке диаграмм **D2** (https://d2lang.com);
- в виде **ASCII-дерева** (по параметру `--ascii-tree`);
- в виде списка связей и списка найденных циклов;
- в виде списка **обратных зависимостей** пакета (для тестового репозитория).

Архитектура - конвейер из четырех шагов:

1. `config` - разбор и проверка параметров командной строки;
2. `sources` - источник данных: `RegistrySource` (npm-репозиторий по URL)
   или `FileRepository` (файл тестового репозитория);
3. `graph` - построение графа алгоритмом BFS с рекурсией (`GraphBuilder`):
   каждый вызов `visit_level` обрабатывает один уровень графа и рекурсивно
   вызывает себя для следующего; множество обнаруженных пакетов гарантирует,
   что пакет обрабатывается один раз, поэтому циклы не зацикливают обход;
4. `report`, `d2`, `ascii_tree` - форматирование результата для вывода.

Режим обратных зависимостей использует тот же `GraphBuilder`: источник
`ReverseSource` возвращает не зависимости пакета, а зависящие от него пакеты.

Структура проекта:

- `src/depviz/` - исходный код (модули описаны в разделе 2.7);
- `tests/` - модульные тесты (`unittest`), локальный HTTP-сервер
  `tests/fake_registry.py`, имитирующий npm-репозиторий (интернет не нужен),
  и тестовые репозитории `tests/data/*.txt`;
- `run.bat` - запуск приложения и тестов в Windows.

Особенности работы с реальным репозиторием:

- для каждого пакета берется последняя версия (`dist-tags.latest`), в граф
  входит поле `dependencies`; `devDependencies`, `peerDependencies` и
  `optionalDependencies` не учитываются;
- узлы графа - имена пакетов, одному имени соответствует один узел;
- алиасы `npm:имя@диапазон` заменяются настоящим именем пакета, зависимости
  из git, URL и файлов пропускаются;
- метаданные запрашиваются по адресу `<репозиторий>/<имя пакета>`, слеш в
  имени пакета с областью видимости кодируется (`@babel/core` ->
  `@babel%2Fcore`);
- пакеты запрашиваются последовательно, для крупных пакетов обход может
  занять десятки секунд.

## 2. Описание всех функций и настроек

### 2.1. Параметры командной строки

| Опция                | Описание                                                                    |
|----------------------|-----------------------------------------------------------------------------|
| `-p`, `--package`    | Имя анализируемого пакета (обязательная).                                   |
| `-r`, `--repo`       | URL репозитория или путь к файлу тестового графа.                           |
| `-t`, `--test-mode`  | Режим тестового репозитория: `--repo` - путь к файлу.                       |
| `-a`, `--ascii-tree` | Дополнительно вывести граф в виде ASCII-дерева (режимы `d2` и `graph`).     |
| `-f`, `--filter`     | Не учитывать пакеты, в имени которых есть подстрока.                        |
| `-s`, `--show`       | Что вывести (режимы вывода описаны ниже), по умолчанию `d2`.               |

Правила проверки:

- обычный режим: имя пакета по правилам npm (строчные буквы, цифры,
  `-._~`, необязательный префикс `@область/`, не длиннее 214 символов);
  `--repo` должен быть адресом `http(s)://хост`, по умолчанию
  `https://registry.npmjs.org`;
- тестовый режим: имя пакета состоит из больших латинских букв `A-Z`;
  `--repo` обязателен и указывает на существующий файл;
- подстрока фильтра непустая, без пробельных символов, регистр учитывается;
  фильтр не должен исключать сам анализируемый пакет;
- неизвестные и сокращенные опции отклоняются.

Фильтр: пакет, в имени которого есть подстрока, не запрашивается, не
попадает в граф, и его собственные зависимости не анализируются (если они не
достижимы другим путем).

### 2.2. Режимы вывода (`--show`)

| Значение  | Что выводится                                                           | Этап |
|-----------|-------------------------------------------------------------------------|------|
| `config`  | Проверенные параметры в формате ключ-значение, без обращения к данным.  | 1    |
| `direct`  | Прямые зависимости пакета (только репозиторий по URL).                  | 2    |
| `graph`   | Список связей графа и список циклов.                                    | 3    |
| `reverse` | Обратные зависимости пакета по уровням (только `--test-mode`).          | 4    |
| `d2`      | Описание графа на языке диаграмм D2 (по умолчанию).                     | 5    |

Флаг `--ascii-tree` добавляет после вывода `d2` или `graph` пустую строку и
ASCII-дерево зависимостей. В режимах `config`, `direct` и `reverse` он не
влияет на вывод.

### 2.3. Формат файла тестового репозитория

Одна строка на пакет: `ПАКЕТ: ЗАВИСИМОСТИ`. Имена - большие латинские буквы,
зависимости разделяются пробелами или запятыми, пустые строки игнорируются.
Пакет, упомянутый только как зависимость, считается пакетом без зависимостей.
Пример (`tests/data/diamond.txt`):

    A: B C
    B: D
    C: D
    D:

### 2.4. Форматы вывода

**D2.** Каждая зависимость - связь `"A" -> "B"`, в порядке обхода BFS. Имена
берутся в двойные кавычки, поэтому `@scope/name`, `lodash.merge` и `left-pad`
записываются корректно. Пакет без связей объявляется отдельной строкой.
Результат можно вставить в https://play.d2lang.com или передать утилите `d2`.

**ASCII-дерево.** Зависимости пакета раскрываются при первой встрече.
Повторная встреча пакета с зависимостями помечается `(*)`, пакет, уже
стоящий выше по цепочке, - `(цикл)`; пояснения выводятся под деревом.

**Список связей (`graph`).** Строка `пакет -> зависимости` для каждого узла в
порядке BFS, затем список циклов. Цикл - цепочка, у которой первый и
последний пакет совпадают; выводится один цикл на каждое обратное ребро
обхода в глубину.

**Обратные зависимости (`reverse`).** Для пакета `--package` находятся все
пакеты тестового репозитория, которые зависят от него напрямую или через
другие пакеты. На уровне 1 - пакеты, зависящие от заданного напрямую, на
уровне 2 - зависящие от пакетов уровня 1 и так далее. Сам пакет в список не
включается, его участие в цикле видно в разделе циклов, где цепочка записана
в направлении `<-` (`A <- C` - `C` зависит от `A`). Реестр npm не хранит
обратных зависимостей, поэтому с репозиторием по URL режим недоступен.

### 2.5. Коды завершения

`0` - успех; `2` - ошибка параметров; `3` - ошибка получения или анализа
данных (нет сети, пакет не найден, статус HTTP не 200, некорректный ответ или
файл, слишком глубокий граф). Сообщение об ошибке выводится в stderr.

### 2.6. Источники данных

- `RegistrySource` - запрашивает метаданные пакета в репозитории по HTTP
  (`urllib`), берет зависимости версии `latest`;
- `FileRepository` - читает файл тестового репозитория (кодировка UTF-8, BOM
  и переводы строк Windows допустимы);
- `ReverseSource` - обертка над `FileRepository`, возвращающая зависимые
  пакеты вместо зависимостей.

## 3. Описание команд для сборки проекта и запуска тестов

Сборка не требуется, нужен только Python 3.9 или новее в `PATH`. Все команды
выполняются в командной строке Windows из корня репозитория.

    run.bat -p express -a
    run.bat -t -p A -r tests\data\diamond.txt -a
    run.bat test

- `run.bat <параметры>` - запуск приложения (`python -m depviz`);
- `run.bat test` - запуск всех модульных тестов из каталога `tests\`
  (`python -m unittest discover -s tests -t . -v`).

Для запуска с реальным репозиторием нужен доступ в интернет к
`registry.npmjs.org`, для тестов и тестового режима - нет. Вывод можно
сохранить в файл (каталог `out\` исключен из git):

    mkdir out
    run.bat -p express > out\express.d2

## 4. Примеры использования

### 4.1. Тестовый репозиторий (пакеты `A`-`K`)

Файлы лежат в `tests\data`: `simple`, `diamond` (общая зависимость), `cycle`
(цикл через корень), `inner_cycle` (цикл внутри графа), `self_loop`
(зависимость от самого себя), `disconnected` (недостижимые пакеты), `chain`,
`mixed` (общие зависимости и цикл).

Общая зависимость: D2 и ASCII-дерево.

    run.bat -t -p A -r tests\data\diamond.txt -a
    "A" -> "B"
    "A" -> "C"
    "B" -> "D"
    "C" -> "D"

    A
    |-- B
    |   `-- D
    `-- C
        `-- D

Цикл через корневой пакет:

    run.bat -t -p A -r tests\data\cycle.txt -a
    "A" -> "B"
    "B" -> "C"
    "C" -> "A"

    A
    `-- B
        `-- C
            `-- A (цикл)

    (цикл) - пакет уже встречается выше по цепочке зависимостей

Смешанный граф: общие зависимости и цикл `A -> D -> H -> A`.

    run.bat -t -p A -r tests\data\mixed.txt -a
    "A" -> "B"
    "A" -> "C"
    ...
    "J" -> "K"

    A
    |-- B
    |   |-- E
    |   |   `-- I
    |   `-- F
    |       |-- I
    |       `-- J
    |           `-- K
    |-- C
    |   |-- F (*)
    |   `-- G
    |       `-- J (*)
    `-- D
        |-- G (*)
        `-- H
            `-- A (цикл)

    (*) - зависимости этого пакета показаны выше
    (цикл) - пакет уже встречается выше по цепочке зависимостей

Фильтр и список связей (пакет `H` исключен, цикл исчез):

    run.bat -t -p A -r tests\data\mixed.txt -s graph -f H
    Граф зависимостей пакета A: узлов 10, ребер 13
    A -> B, C, D
    B -> E, F
    C -> F, G
    D -> G
    E -> I
    F -> I, J
    G -> J
    I -> (нет зависимостей)
    J -> K
    K -> (нет зависимостей)
    Циклические зависимости: не обнаружены

Зависимость пакета от самого себя и недостижимые пакеты (`X`, `Y` не
выводятся):

    run.bat -t -p A -r tests\data\self_loop.txt
    "A" -> "A"
    "A" -> "B"

    run.bat -t -p A -r tests\data\disconnected.txt
    "A" -> "B"

Обратные зависимости (общая зависимость `D`, цикл вдали от пакета `K`):

    run.bat -t -p D -r tests\data\diamond.txt -s reverse
    Обратные зависимости пакета D (всего 3):
      уровень 1: B, C
      уровень 2: A
    Циклические зависимости: не обнаружены

    run.bat -t -p K -r tests\data\mixed.txt -s reverse
    Обратные зависимости пакета K (всего 8):
      уровень 1: J
      уровень 2: F, G
      уровень 3: B, C, D
      уровень 4: A
      уровень 5: H
    Циклические зависимости (1):
      A <- H <- D <- A

Параметры и ошибки:

    run.bat -p express -a -f test -s config
    package: express
    repo: https://registry.npmjs.org
    test_mode: false
    ascii_tree: true
    filter: test
    show: config

    run.bat -t -p Z -r tests\data\simple.txt
    Ошибка: пакет 'Z' не найден в репозитории 'tests\data\simple.txt'
    run.bat -t -p A -r tests\data\simple.txt -f A
    Ошибка: пакет 'A' содержит подстроку фильтра 'A' и был бы исключен из анализа
    run.bat -p express -s reverse
    Ошибка: режим reverse работает только с тестовым репозиторием (--test-mode): ...

### 4.2. Визуализация трех реальных пакетов

Для демонстрации выбраны три пакета разного размера: `debug` (одна
зависимость), `@babel/code-frame` (имя с областью видимости, несколько
зависимостей) и `express` (крупный граф с общими зависимостями).

    run.bat -p debug -a
    run.bat -p @babel/code-frame -a
    run.bat -p express -a

Список связей и циклов для любого из них: `run.bat -p express -s graph`;
прямые зависимости: `run.bat -p express -s direct`. Граф зависит от даты
запуска: берутся последние версии пакетов на этот момент.

### 4.3. Сравнение со штатными инструментами npm

Штатный инструмент визуализации - `npm ls --all`, он печатает дерево
установленных пакетов. Чтобы получить дерево для того же пакета, его
устанавливают во временный проект (скрипты установки отключены) и выводят
дерево:

    mkdir %TEMP%\npmcheck_express
    cd /d %TEMP%\npmcheck_express
    npm init -y
    npm install express --ignore-scripts
    npm ls --all

Сравнивать удобно множество имен пакетов: в выводе `depviz` это уникальные
имена в связях D2 (или в ASCII-дереве), в выводе `npm ls` - имена перед
символом `@` версии. Возможные расхождения и их причины:

1. **Версии.** `depviz` берет для каждого пакета последнюю версию, а `npm`
   выбирает наибольшую версию, удовлетворяющую диапазону `semver` из
   `dependencies` родителя. Если в последней версии пакета набор зависимостей
   другой, графы различаются.
2. **Несколько версий одного пакета.** `npm` может установить разные версии
   пакета в разные места дерева, в `depviz` одному имени соответствует один
   узел.
3. **Типы зависимостей.** `depviz` учитывает только `dependencies`. `npm` 7+
   дополнительно устанавливает `peerDependencies` и (при совместимой
   платформе) `optionalDependencies`, `npm ls` их показывает.
4. **Корень.** `npm ls` начинается с временного проекта, а `devDependencies`
   устанавливаются только для корневого проекта, поэтому на сравнение они не
   влияют.
5. **Повторы.** `npm ls` помечает повторные вхождения как `deduped`,
   `depviz` - как `(*)` и `(цикл)`; в списке связей и в D2 каждая связь
   присутствует один раз.
6. **Нестандартные источники.** Алиасы `npm:` разворачиваются, а зависимости
   из git, URL и файлов `depviz` пропускает, `npm` их устанавливает.
7. **Время.** Оба инструмента отражают состояние реестра на момент запуска;
   публикация новых версий меняет результат.
